### 5.3 读法

- **平台差异是真实存在的**。同一个 `glm-5.3`，`zcode` 351.01、`qoder` 345.50，
  差 5.5 分；`deepseek-v4` 系列里 `DSV4F0731` 311.02、`DSV4F-VE-OCGO` 245.70，
  差距更大。不要把「模型名」当成「跑分」。
- **榜单把 `qwen3.8-flash` 推成全能型**：四项都在本仓已配模型的前二
  （文字 96.19、后端 94.00、知识 91.71、前端 91.05）。但它在 ZCode 侧走
  `opencode-go-messages`，不是主力 chat；要把它提成默认，先验证协议与工具调用，
  不能只按分数搬。
- `deepseek-v4.1-flash` 没有单项第一，但四项都进前三，是「无短板」型；
  本仓选它当主力还因为额度最大（$80 / 133M）。榜单分数解释不了主力选择，
  成本与稳定性才是主因。
- `minimax-m3` 在榜上偏低（#25，279.78），主要拖累是前端 66.28；本仓只把它当长上下文用，
  与榜单结论不冲突。
- `hy4-preview` 的前端 / 知识最高，但它在 WorkBuddy 侧，受账号池与免代 / 高代倍率影响；
  榜上的 `HIGH` 档不等于本仓分组。
- **方向标签与性价比档都是第二轴，不替代 provider 分档**。provider 分组仍按协议 / 成本 / 额度，
  见 MODEL-PROVIDERS §2 / §4；方向与性价比只决定「同一档里优先用谁」。

### 5.4 以 DeepSeek 为基准的性价比分档

口径：**2026-09-11 榜上总分 + 本仓 2026-10-19/21 价格**。
基准 = `deepseek-v4.1-flash`：总分 **342.40**，OpenCode-Go 输出单价上限 **$1.20/M**，
WorkBuddy 倍率 **0.11**。

- **智力指数** = 总分 ÷ 342.40 × 100；
- **价格指数** = 输出单价 ÷ 1.20 × 100（WorkBuddy 用倍率 ÷ 0.11 × 100）；
- **性价比** = 智力指数 ÷ 价格指数；免费模型不算性价比；
- **分档规则**（优先级从上到下）：
  1. **免费**：价格 = 0；
  2. **主力**：智力 ≥ 100 且 价格 ≤ 100；
  3. **低耗**：价格 < 100 且（智力 ≥ 85 或 性价比 ≥ 1.2）；
  4. **高耗**：智力 > 100 且 价格 > 100；
  5. **备用**：其余（性价比 < 1，或又笨又贵）。

## 6. 怎么用、别怎么用

**可以这样用：**

- 在 [MODEL-PROVIDERS.md](MODEL-PROVIDERS.md) §6「一句话选择」之外，补一个**质量侧参考**：
  同一价位带里谁在长任务上更稳。
- 排查「某个模型是不是不行」时，先看它在榜上的方向分，判断是**模型问题**还是
  **本仓接入 / 参数问题**（例如前端分正常、后端分为 0，更像任务或协议问题）。
- 挑新模型时看**逐题榜**，比总分更接近具体用途（写作、前端、后端修复、科学模拟）。

**不要这样用：**

- **不要当百分制**。归一分可以超过 100（例：GPT-6-ASTRA 后端 103.10），
  总分 400 也只是「四方向相加」的参考上限。
- **不要当重复实验**。31 个测评、每个配置一次，站点没有给方差、置信区间或重跑次数；
  几分以内的差距不足以区分模型。
- **不要跨平台横比**。同一模型在不同客户端 / 网关下的分数不同（见 §5），
  榜上的平台列必须一起读。
- **不要替代本仓探测**。本仓脚本测的是**连通性、协议、首字延迟、倍率与额度**
  （见 [TOOLS.md](TOOLS.md)、[MAINTENANCE.md](MAINTENANCE.md)）；
  这个榜测的是**任务质量**。两者互补，不能互相证明。
- **不要把它写成本仓实测**。本仓的实测证据在 `evidence/`；本篇只是外部快照。
